## Phase 0: Research

### Unknowns Found

1. **Outlines compatibility with Qwen3-VL multimodal encoder-decoder**: Does `outlines.from_transformers()` correctly wrap Qwen3VLForConditionalGeneration when images are passed alongside text?
2. **Processor initialization for Qwen3-VL**: Are there specific `AutoProcessor` configuration nuances (e.g., image preprocessing, token padding behavior) that differ from prior Qwen-VL releases?
3. **Generator behavior with vision-language `inputs.Chat()`**: Does Outlines' `inputs.Image()` multimodal helper integrate with the tokenizer's image token format (`<|vision_start|>` etc.) without manual intervention?

### Research Tasks

```text
Task 1 (Phase 0): "Research Outlines from_transformers compatibility with Qwen3-VL-2B-Instruct for multimodal structured generation."
Task 2 (Phase 0): "Research correct AutoProcessor initialization for Qwen3-VL, including trust_remote_code and image preprocessing settings."
Task 3 (Phase 0): "Research Outlines Generator with Pydantic schema on VL models: verify inputs.Chat().add_user_message() with inputs.Image() works with Qwen3-VL."
```

### Findings Consolidated (research.md)

**Decision**: Keep Outlines + Pydantic pipeline; adapt initialization only.

**Rationale**: The constitution explicitly mandates structured outputs. Outlines' `from_transformers` wrapper and `Generator` with Pydantic schemas are the current implementation's architecture. The only variable is ensuring this wrapper works correctly for the specific Qwen3-VL-2B-Instruct model rather than a different model identifier. The multimodal `inputs.Image()` pattern is the documented Outlines approach for vision-language models.

**Alternatives considered**:
- Switch to `lm-format-enforcer` for structured decoding — rejected because the current implementation already uses Outlines and the user explicitly instructs not to change dependencies.
- Switch to unconstrained `model.generate()` with regex parsing — rejected by constitution (Section 6).

**Adapter strategy**: If `from_transformers` requires explicit model class dispatch or processor configuration tweaks for Qwen3-VL, those changes must live entirely inside `load_model_and_processor()` and `run_inference()`. No signature changes on exported functions.
