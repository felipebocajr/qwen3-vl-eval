# Project Constitution: Qwen3-VL MMMU Evaluation Pipeline

## Objective
Build a fully-working local evaluation pipeline that loads Qwen3-VL-2B-Instruct, runs inference on 100 samples from the MMMU (Massive Multi-discipline Multimodal Understanding) dataset, and produces structured results + summary metrics.

---

## Project Deliverables

- **Working pipeline** that loads Qwen3-VL-2B-Instruct locally, runs it on 100 MMMU samples, and produces results end-to-end
- **`trajectories.jsonl`** - one structured JSON record per sample with: sample ID, subject, question, choices, correct answer, full prompt sent, raw model response, extracted answer, extraction success flag, correctness flag, inference time, and error field
- **`summary.json`** - aggregate metrics: overall accuracy, per-subject accuracy, parse failure rate, inference error count, average inference time, total runtime
- **Resumability** - if the pipeline is killed at sample 60 and restarted, it picks up from sample 61 without re-running completed samples
- **`README.md`** - setup instructions (clone → `uv sync` → run), any issues encountered, and a brief analysis (3-5 sentences) of the results
- **`pyproject.toml` + `uv.lock`** - pinned dependencies for reproducibility
- **Modular code** - separated into logical components (model set up and loading, data loading, answer parsing, pipeline loop, metrics). Exact file structure is up to you.

---

## Tech Stack

- **Python 3.12**
- **uv** for dependency management and virtual environment
- **Transformers / vLLM** (or whichever library successfully loads Qwen3-VL-2B-Instruct)
- **Datasets library** (Hugging Face) for loading MMMU data
- **JSONL** for per-sample structured output
- **JSON** for aggregate summary metrics

---

## Key Design Principles

1. **Resumability first** — Completed samples must not be re-run. Use `trajectories.jsonl` as the source of truth for resume state.
2. **Fail gracefully** — If a sample errors (OOM, parse failure, etc.), log the error and continue with the next sample.
3. **Determinism** — Pin all dependencies in `uv.lock`. Document any manual steps.
4. **Modularity** — Separate concerns: data loading, model inference, parsing, metrics, and orchestration should be in distinct modules.
5. **Minimal dependencies** — Only add packages that are strictly necessary.
6. **Output brevity** — The prompt and generation configuration must be designed to produce *concise* answers (ideally a single letter) so that responses are not truncated before the answer is emitted. If reasoning chains or `<think>` tags are generated by default, they must be suppressed or the answer must be extracted from the *end* of the output.

---

## Data Requirements

- Load 100 samples from the MMMU dataset (HuggingFace `MMMU/MMMU`).
- Use stratified sampling across subjects if possible, or simply take the first 100 if stratification is non-trivial.
- Fields to capture per sample:
  - `id`, `subject`
  - `question`, `choices`, `answer` (ground truth)

## Output Requirements

### `trajectories.jsonl` (one record per sample)
```json
{
  "sample_id": "...",
  "subject": "...",
  "question": "...",
  "choices": ["A", "B", "C", "D"],
  "correct_answer": "A",
  "prompt": "...",
  "raw_response": "...",
  "extracted_answer": "A",
  "extraction_success": true,
  "is_correct": true,
  "inference_time_sec": 12.34,
  "error": null
}
```

### `summary.json`
```json
{
  "overall_accuracy": 0.35,
  "per_subject_accuracy": {"Art": 0.4, "Biology": 0.3},
  "parse_failure_rate": 0.02,
  "inference_error_count": 3,
  "average_inference_time_sec": 10.5,
  "total_runtime_sec": 1050.0
}
```

## File Structure (Flexible)

Suggested layout:
```
├── src/
│   ├── __init__.py
│   ├── data_loader.py      # MMMU dataset loading
│   ├── model_wrapper.py    # Qwen3-VL model setup & inference (must enforce short answers / disable thinking / truncate reasoning chains)
│   ├── parser.py           # Extract answer from raw model response (must handle truncation and  <think>  blocks)
│   ├── pipeline.py         # Main loop with resume logic
│   ├── metrics.py          # Accuracy, per-subject stats, etc.
│   └── config.py           # Paths, constants, sample count, generation params
├── trajectories.jsonl
├── summary.json
├── README.md
├── pyproject.toml
└── uv.lock
```

## Workflow

1. **Setup**: `uv sync` installs all pinned dependencies.
2. **Run**: `python -m src.pipeline` (or equivalent entry point).
3. **Resume**: Re-running the script reads `trajectories.jsonl`, skips completed IDs, continues from the next sample.
4. **Report**: On completion, `summary.json` is written alongside `trajectories.jsonl`.

## Constraints

- All code must be human-maintainable (no 500-line functions).
- No hardcoded API keys or personal paths.
- Model must be loaded locally — no remote inference APIs.
- If Qwen3-VL-2B-Instruct requires specific handling (e.g. special image tokens, chat template quirks), document it in a comment or README subsection.
- **Prompt truncation mitigation** — The model prompt must explicitly instruct the model to answer with *only* the letter (e.g. `"Answer with the option's letter from the given choices directly. Output ONLY the letter and nothing else."`). If the model supports reasoning/thinking modes that produce verbose output, the generation configuration should disable them or the structured output should be constrained (e.g. via `enable_thinking=False`, forced short decoder parameters, or tool-calling) so the raw response does not get truncated mid-answer.
- **Non-null extraction target** — Truncated or malformed raw responses should still yield a best-effort `extracted_answer`. For example, if the response is cut off, the parser should attempt to infer the answer from the last visible option letter, or mark it as a parse failure rather than silently returning null.
